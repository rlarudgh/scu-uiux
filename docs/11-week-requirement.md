10주차까지 제작한 본인의 서비스 웹페이지에 11주차에서 학습한 웹 접근성 원칙을 적용하세요. 다양한 사용자가 정보를 이해하고 주요 기능을 이용할 수 있도록 화면과 코드를 개선하는 과제입니다.

[과제 요구사항]

1. 색 대비와 정보 전달
   글자와 배경을 구분하기 쉽도록 색상을 점검하고 개선합니다. 오류나 선택 상태는 색상뿐 아니라 문구·기호 등으로도 구분할 수 있도록 구현합니다.

2. 대체 텍스트와 명확한 라벨
   정보 전달용 이미지에는 의미에 맞는 대체 텍스트(alt)를 작성합니다. 이미지가 없는 경우 과제를 위해 추가할 필요는 없습니다. 입력 항목에는 연결된 라벨을 제공하고, 버튼과 링크에는 기능을 이해할 수 있는 이름을 작성합니다.

3. 키보드 접근과 초점 표시
   마우스 없이 Tab, Shift+Tab, Enter 등의 키로 주요 기능을 이용할 수 있도록 점검합니다. 현재 선택된 요소를 알 수 있도록 초점 표시를 제공하고, 이동 순서가 자연스럽게 이어지도록 수정합니다.

4. 읽기 쉬운 구조와 개선 내용 정리
   제목과 본문을 적절히 구분하고, 안내 및 오류 메시지를 이해하기 쉽게 작성합니다. 제출 본문에 접근성을 개선한 내용 3가지 이상을 ‘개선 전 → 개선 후’ 형식으로 간단히 설명합니다.

[제출 방법]

기존에 사용하던 GitHub 저장소와 배포 웹페이지를 업데이트한 후, 과제 제출 본문에 다음 내용을 작성하세요.

1. 서비스명 및 간단한 소개
2. GitHub 저장소 주소
3. 배포 웹페이지 주소
4. 접근성 개선 내용 3가지 이상

※ 수업 예제를 참고하되, 본인이 기획한 서비스에 맞게 적용해야 합니다.
※ 제출 전 두 주소의 접속 가능 여부와 배포 페이지에 수정 사항이 반영되었는지 확인하세요.
