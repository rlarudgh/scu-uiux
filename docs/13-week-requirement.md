12주차까지 만든 본인 웹 프로토타입에서 사용자가 작성 중이던 과업을 새로고침 뒤에도 이어갈 수 있도록 개선합니다.

1. 과업 기반 QA
   대표 과업을 하나 정하고 최종 저장 전에 새로고침해 보세요. 시작 조건, 행동, 기대 결과, 실제 결과, 예상 사용자 영향을 README.md에 기록합니다.

2. 작성 상태 복구 구현
   입력값·선택값·진행 단계를 임시 보관하고, 같은 탭을 새로고침했을 때 작성 중이던 화면과 안내를 복구하세요. 처음부터 다시 시작하거나 최종 저장에 성공하면 임시값이 지워지는지도 확인합니다.

3. 사용자 테스트와 재검증
   복구 기능을 구현한 뒤, 본인 서비스를 사용할 가능성이 있는 사람 1명 이상에게 대표 과업과 다른 경로 과업을 하나씩 제시합니다. 과업의 목표와 상황을 알려 주고 클릭 순서는 알려 주지 않습니다. 교안의 양식 A~E를 활용해 과업 조건, 실제 행동과 발화, 도움 여부, 사후 응답을 남기세요. 1차 관찰에서 발견한 문제를 수정한 뒤 가능하면 같은 참여자에게 같은 과업을 다시 수행하게 합니다. 1·2차 결과와 반복 수행의 영향을 기록하고, 기능 회귀 QA 결과는 통과·실패·미확인으로 표시합니다.

4. 제출
   LMS 제출란에 본인 GitHub 저장소 주소와 배포 웹페이지 주소를 적어 주세요. README.md에 QA, 양식 A~E의 기록, 수정·재검증 결과를 작성하거나 저장소 안의 기록 파일로 연결합니다. 참여자는 P01처럼 코드로 표기하고, 촬영과 공개에 동의한 경우에만 개인정보가 보이지 않는 테스트 장면 사진 1장을 README에 연결하세요.
