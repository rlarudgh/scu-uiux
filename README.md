# 책갈피

하루 한 줄씩 독서 기록을 남기는 서비스 소개 페이지입니다.

배포 주소: https://rlarudgh.github.io/scu-uiux/

## 검사와 배포

```sh
./deploy.sh check             # HTML·CSS·JS 검사만 (Node.js, Java 필요)
./deploy.sh "feat: 메시지"     # 검사 → 변경 파일 확인(y/N) → 커밋 → main push
```

- GitHub Pages가 `main` 브랜치에서 배포되므로 push하면 1~2분 뒤 사이트에 반영됩니다.
- CI(`.github/workflows/ci.yml`)는 `main` push와 PR마다 같은 `./deploy.sh check`를 실행합니다. 검사 결과만 보여주며 배포를 막지는 않습니다.
- 설정 파일 없이 `npx`로 버전을 고정해 실행합니다. HTML·CSS는 W3C 공식 검사기(vnu), JS는 ESLint이며 규칙은 `deploy.sh` 안에 있습니다.

## 서비스 소개

- 사용자: 책을 꾸준히 읽고 싶은 20~30대 독서 초보자
- 목적: 독서 목표를 정하고 짧은 기록을 남기며 독서 습관 만들기
- 핵심 행동: 독서 목표 등록

## 사용자 흐름 (7주차)

시작 → 책 입력(검색 또는 직접 입력) → 목표 선택 → 확인 → 완료

- 필수값(제목, 주기, 분량)이 비면 항목별 오류 안내, 다음 단계로 못 넘어감
- 이전/수정으로 돌아가도 입력값 유지, 다시 시작하면 확인 모달 → 전체 초기화
- 완료 후 "첫 기록 남기러 가기"로 한 줄 기록 탭에 책 제목 자동 입력

## 13주차: 작성 중 새로고침 복구와 사용자 테스트

### QA · 작성 중 새로고침 (수정 전, Chrome · 로컬)

- 시작 조건: 독서 목표 만들기에서 검색 "아몬드" → 『아몬드 · 손원평 (264쪽)』 선택
- 선택 상태: 독서 주기 매일, 하루 목표 20쪽, 알림 받기 21:00 · 앱 푸시, **4단계(확인)** 화면
- 행동: '목표 등록'을 누르기 전에 새로고침
- 기대 결과: 책·주기·분량·알림이 남고 4단계 요약이 그대로 보임
- 실제 결과: "1 / 5 단계 · 시작" 빈 화면이 열림. 책 제목·검색어·주기·분량·알림이 모두 비어 있음
- 사용자 영향(예상): 책을 다시 검색해 고르고 주기·분량·알림 시간을 다시 골라야 함. 4단계를 다시 지나야 등록 가능
- 원인 가설(코드 확인): 작성 값이 `goalState`(메모리)에만 있고 등록 전에는 어디에도 저장되지 않음
- 재확인: 같은 값·같은 4단계에서 새로고침해 요약이 같은지 확인 → 아래 회귀 QA 1번

## 12주차: 재사용 가능한 UI 컴포넌트

| 컴포넌트 | 위치 | 사용 목적 | 동작 방법 | 상태 표시 |
| -------- | ---- | --------- | --------- | --------- |
| 탭 (기존 → 개선) | 독서 기록하기 | 한 줄 기록·독서 캘린더·완독 목록을 한 자리에서 전환 | 클릭, ←/→ 이웃 탭, Home/End 처음·마지막 탭 | 선택 탭 굵은 글씨 + 초록 밑줄 + 배경, `aria-selected` |
| 아코디언 (신규) | 이용 방법 > 자주 묻는 질문 | 저장 위치·직접 입력·다시 시작·키보드 사용 안내를 접어 두어 페이지 길이를 줄임 | 질문 버튼 클릭 또는 Enter/Space로 열고 닫기 (여러 개 동시 열기 가능) | "펼치기 +" ↔ "접기 −" 문구, 열린 질문은 배경색과 왼쪽 초록 선, `aria-expanded` |
| 모달 (신규) | 독서 목표 만들기 완료 화면의 "다시 시작" | 버튼 한 번에 입력이 바로 지워지던 문제를 막고 지워지는 범위를 미리 안내 | "다시 시작" → 확인 창. "취소"·Esc·바깥 클릭이면 닫힘, "입력 내용 지우고 다시 시작"이면 1단계로 초기화 | 어두운 배경으로 뒤 화면 비활성, 열리면 "취소"에 초점 |

### 재사용 구조

- **CSS 클래스**: `.tab-list`/`.tab`/`.is-active`, `.accordion`/`.accordion-trigger`/`.accordion-panel`/`.accordion-state`, `.modal`/`.modal-content`/`.modal-title`/`.modal-actions`. 버튼은 기존 `.btn-primary`/`.btn-secondary` 재사용
- **탭 개선**: 전에는 페이지의 모든 `[role='tab']`을 한꺼번에 잡아 탭 그룹이 2개가 되면 서로 섞였음 → `initTabs(tablist)`가 `data-tabs` 목록마다 따로 동작, 탭마다 붙이던 리스너를 목록 하나의 이벤트 위임으로 변경
- **아코디언**: `data-accordion` 컨테이너에 클릭 리스너 하나(이벤트 위임), `setAccordionOpen(trigger, isOpen)`이 `aria-expanded`·패널 `hidden`·문구를 함께 바꿈. HTML 항목만 추가하면 JS 수정 없이 늘어남
- **모달**: 어떤 버튼이든 `data-modal-open="모달 id"`만 붙이면 열림(문서 전체 이벤트 위임). `<dialog>` 안 `<form method="dialog">` 버튼의 `value`로 결과를 구분하고, 확인 시 실행할 함수는 `MODAL_CONFIRM_ACTIONS`에 id별로 등록

### 접근성

- 탭: `role="tablist/tab/tabpanel"`, `aria-controls`, 선택된 탭만 `tabindex=0`(Tab 한 번으로 탭 목록 통과)
- 아코디언: 질문을 `<h4>` 안의 `<button>`으로 만들어 Enter/Space 기본 지원, `aria-expanded`·`aria-controls`로 열림 상태 전달, 보이는 "펼치기/접기" 문구는 중복 낭독을 막기 위해 `aria-hidden`
- 모달: 네이티브 `<dialog>`의 `showModal()`로 초점 가두기·Esc 닫기·뒤 화면 비활성, `aria-labelledby`/`aria-describedby`로 제목·설명 연결, 취소 시 "다시 시작" 버튼으로 초점 복귀, 확인 시 1단계 제목으로 초점 이동
- 버튼 이름: "확인" 대신 "입력 내용 지우고 다시 시작"처럼 결과를 그대로 적음. 모든 버튼에 11주차의 파란 `:focus-visible` 테두리 적용

## 11주차: 웹 접근성

### 개선 전 → 개선 후

| 영역 | 개선 전 | 개선 후 |
| ---- | ------- | ------- |
| 색 대비 | 글자 수 카운터·빈 목록 안내(`#777`, 약 4.5:1 미만), 진행 단계 이름(`#888`, 약 3.5:1)이 흰 배경에서 흐리게 보임 | 모두 `#595959`(약 7:1)로 바꿔 WCAG AA(4.5:1) 이상 확보 |
| 색 외 정보 전달 | 독서 캘린더의 기록한 날, 진행 단계의 완료 단계를 초록색으로만 구분 | 기록한 날에 "✓"와 스크린 리더용 "기록함/기록 없음·오늘" 문구, 완료 단계 숫자 앞에 "✓" 추가 |
| 초점 표시 | 탭·선택 버튼에만 얇은 초록 테두리, 나머지는 브라우저 기본값이라 초록 버튼 위에서 잘 안 보임 | 링크·버튼·입력·선택 상자 모두 같은 3px 진한 파란 테두리(`:focus-visible`)로 통일 |
| 키보드 이동 | 페이지 처음에 Tab을 누르면 메뉴 5개를 모두 지나야 본문에 도착, 탭은 ←/→만 지원 | 첫 Tab에 "본문으로 건너뛰기" 링크 표시 → Enter로 `main`으로 이동. 탭에 Home/End 추가 |
| 이메일 폼 오류 | 빈 값이면 버튼이 비활성화되어 "왜 못 누르는지" 안내가 없음. 오류 문구가 입력 칸과 연결되지 않고 "형식이 아니에요"만 표시 | 버튼은 항상 활성화하고 제출 시 검증. 오류 시 `aria-invalid`, 입력 칸으로 포커스, `aria-describedby`로 도움말·오류 연결, "'@'와 도메인을 포함해 입력해주세요. 예: you@example.com"처럼 수정 방법 안내 |
| 한 줄 기록 폼 라벨 | 필수 여부 표시가 없고, "기록하기"가 비활성일 때 이유를 알 수 없음. 글자 수 카운터가 입력과 연결되지 않음 | 라벨에 "(필수)", "(필수, 50자 이내)" 표시, 버튼 사용 조건 안내 문구 추가, 카운터·안내를 `aria-describedby`로 연결 |
| 제목 구조 | 탭 제목이 `ui&ux programming`, 섹션 제목(주요 기능, 시작하기)이 메뉴 이름(독서 기록하기, 오픈 알림 신청)과 달라 위치를 헷갈림 | 탭 제목 "책갈피 - 하루 한 줄 독서 기록", 섹션 `h2`를 메뉴 이름과 같게 맞춤 (`h1` → 섹션 `h2` → 단계 `h3` 순서 유지) |

이미 적용되어 있던 항목: 대표 이미지 `alt`, 모든 입력의 `label` 연결, 필터 `aria-pressed`+"✓", 메뉴 `aria-current`, 모바일 메뉴 `aria-expanded`·Esc 닫기, 목표 폼 오류의 `aria-invalid`·`aria-live`.

## 10주차: 메뉴 이동과 목록 탐색

### 추가·수정한 기능

- 주요 메뉴: `nav > ul > li > a` 구조로 바꾸고, 목적지를 알 수 있게 메뉴 이름 변경
- 현재 위치 표시: 현재 섹션 메뉴에만 `aria-current="location"`과 `is-current`(채운 배경·굵게·밑줄) 적용, 나머지 메뉴에서는 제거
  - 메뉴 클릭·뒤로 가기(`hashchange`), 새로고침(`load`), 직접 스크롤(`scroll`) 모두 실제 화면 위치로 다시 계산
- 한 줄 기록 필터: 읽기 상태로 거르기. 선택 버튼 표시(✓·채운 배경), `aria-pressed`, 목록, 개수 문구가 함께 바뀜
- 모바일 메뉴(768px 이하): "메뉴 열기" 버튼으로 펼치고 접기. 메뉴 표시, 버튼 문구(열기/닫기), `aria-expanded`가 함께 바뀜. 메뉴를 고르면 이동 후 닫히고, Esc로도 닫힘

## 9주차: 입력 폼 피드백 (독서 목표 만들기 폼)

### 추가·수정한 기능

- 입력 도움말: 제목·독서 주기·하루 분량·알림 시간 아래에 조건 안내를 넣고 `aria-describedby`로 연결
- 실시간 카운터: 제목을 입력하는 동안 `0 / 30자 · 책 제목을 입력해주세요` → `3 / 30자 · ✓ 조건 충족`. 색과 문구를 함께 바꿈
- 조건부 입력: "알림 받기"를 체크하면 알림 시간·알림 방법 영역이 나타남. 체크를 풀면 영역이 숨겨지고 안쪽 입력이 `disabled`로 바뀌며 오류도 사라짐
- 제출 처리: 4단계 "목표 등록"을 누르면 버튼이 비활성화되고 "등록 중…"과 "목표를 저장하고 있어요…"가 표시됨 → localStorage(`bookmark-goals`)에 저장
  - 성공: 완료 화면으로 이동
  - 실패: 4단계에 그대로 남아 입력값이 유지되고, 원인과 해결 방법을 오류 문구로 안내함. 버튼은 "다시 시도"로 바뀜

### 입력 조건

| 항목      | 조건                       | 오류 문구                                |
| --------- | -------------------------- | ---------------------------------------- |
| 책 제목   | 필수, 공백 제외 1~30자     | 책 제목을 입력해주세요. (1~30자)         |
| 독서 주기 | 필수, 하나 선택            | 독서 주기를 하나 선택해주세요.           |
| 하루 분량 | 필수, 목록에서 선택        | 하루 목표 분량을 목록에서 골라주세요.    |
| 알림 시간 | 알림 받기를 체크했을 때만 필수 | 알림 시간을 선택해주세요. 예: 오후 9:00 |

조건을 충족하지 못하면 다음 단계나 제출로 넘어가지 않고, 첫 번째 오류 항목으로 포커스가 이동하며 "필수 항목 N개를 확인해주세요"를 표시합니다. 값을 고치면 해당 오류는 바로 사라집니다.

### 실패 처리 (`script.js`)

| 실패 조건                                      | 코드 위치                       | 안내                                                 |
| ---------------------------------------------- | ------------------------------- | ---------------------------------------------------- |
| 같은 책 제목의 목표가 이미 저장되어 있음        | `saveGoal` → `Error("duplicate")` | "이미 『제목』 목표가 등록되어 있어요. 책 '수정'을 눌러…" |
| localStorage 쓰기 오류 (용량 초과, 저장 차단)   | `saveGoal`의 try/catch → `Error("storage")` | "목표를 저장하지 못했어요. 입력한 내용은 그대로 있으니…" |

`completeGoal`이 오류를 받아 `SUBMIT_ERRORS`의 문구를 표시하고 버튼을 "다시 시도"로 바꿉니다. 중복 제출은 `goalState.submitting`과 버튼 `disabled`로 막습니다.
같은 제목으로 다시 등록하면 실패를 재현할 수 있습니다.

## 중간고사 추가 기능: 책 검색으로 고르기

2단계 "책 입력"(흐름 중간)에 **책 검색 → 결과에서 선택** 경로를 추가했습니다. 고른 책의 쪽수가 확인 화면과 완료 화면의 완독 예상일에 반영됩니다.

| ---------------- | -------------------- | -------------------------------------------- | ------------------------------------------------------------ | --------------------- |
| 검색 (클릭/Enter) | 공백 제외 1자 이상   | "검색 결과 N권" + 결과 카드                  | 빈 값: 오류 문구 / 결과 없음: [다른 검색어로 찾기] [직접 입력하기] | 책 선택 / 재검색      |
| 이 책 선택       | -                    | 제목·저자 자동 입력, 카드 강조, 선택한 책 표시 | 선택 취소: 제목·저자 비움 / 제목 직접 수정: 선택 해제        | 다음                  |
